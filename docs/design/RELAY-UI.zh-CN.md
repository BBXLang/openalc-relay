# Relay 三端首屏界面规范

日期：2026-11-05。用户提供 ChatGPT Android App 截图并指出此前的卡片式仪表盘与目标不符。此版以该截图为直接参考：浅色整屏、中央留白、顶部两个圆形控件与居中的双标签、底部白色悬浮操作栏。截图仅作为设计输入，不入库；Relay 保持自己的名称、功能和标识。

## 布局

| 区域 | 三端约定 |
| --- | --- |
| 背景 | 近白色 `#FAFAFA`，主文字 `#111111`，次要文字 `#838383` |
| 顶部 | 左侧圆形菜单；中间浅灰 `#E9E9E9` 双标签「收件箱／设备」，选中项为白色；右侧圆形 Relay 字母标记 |
| 空收件箱 | 默认保留留白，不放欢迎卡、统计卡或虚构会话 |
| 有数据 | 仅显示真实持久化的合成事件元数据，使用简单行与细分隔线；不造联系人、短信预览或会话 |
| 底部 | 白色圆角悬浮栏；左侧加号打开验证信息／操作；中间是当前可用的本地筛选或安装 ID；右侧黄色 `#FFD12E` 操作位 |

Android 右侧操作位立即尝试本机合成同步，失败后由 WorkManager 重试；中间按事件 ID 筛选 Room 记录；Android 的 fixture、计数、暂停开关、安装 ID 放在菜单内。Web 中间输入安装 ID、右侧手动读取 collector，菜单说明本机合成范围。HarmonyOS 为可构建的 ArkUI Stage 界面工程，底栏明确写「尚未连接服务」，不伪装可查询或发送；平板视口限制导航、内容与底栏宽度。

Web 桌面视口继续沿用同一顶部与底部结构，并限制内容宽度。三端均使用中文文案，不复制 ChatGPT 的名称、语音入口或品牌图案。所有入口应可用或明确说明尚不可用；不放无行为的发送、录音、真实短信按钮。

## 数据与验证边界

- Android 最近 50 条来自 Room `outbox_events` 的只读 Flow。用户在本机按按钮保存固定格式的合成 fixture，不授予短信接收权限也可完成；没有真实短信发送。
- Web 读取 loopback collector 已提交的 SQLite 合成事件，按安装 ID 与 UUID 游标分页。安装 ID 仅作筛选，不是认证。
- HarmonyOS 使用本机 DevEco Studio 与 API 26 SDK 完成构建，并在 HarmonyOS 7.0.0 手机、平板模拟器启动和查看界面；真机安装、权限及行为仍为 `Needs Verification`。详见 [验证记录](../development/HARMONY-UI-2026-11-05.md)。
- 当前 API 不含联系人、正文、号码或未接来电。正式会话、设备配对、搜索正文、远程发送和推送需等待鉴权、授权、加密存储及真实业务 API。

验收时分别检查空态、合成事件列表、底部输入、菜单、状态栏对比度、横向溢出。浏览器手机视口不代替 Android 或 HarmonyOS 真机结论。
