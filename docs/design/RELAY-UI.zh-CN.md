# Relay 三端界面规范

日期：2026-11-06（v2，正式 UI）。v1（2026-11-05，首屏 PoC 规范）保留在文末历史章节，其中仅适用于合成验证入口的约定继续有效，不适用于正式界面。规格来源与验收矩阵见 [FORMAL-UI-MAIL-PLAN](../development/FORMAL-UI-MAIL-PLAN.zh-CN.md)。

## 1. 设计令牌

三端共享以下令牌；代码中必须集中定义（Web：`src/tokens.css` CSS 变量；Android：`theme/RelayTheme.kt`；HarmonyOS：`resources/{base,dark}/element/color.json`），禁止散落硬编码。

| 语义 | 亮色 | 暗色 |
| --- | --- | --- |
| 背景 | `#FAFAFA` | `#111214` |
| 表面（卡片/悬浮栏/侧栏） | `#FFFFFF` | `#1D1E20` |
| 主文字 | `#111111` | `#F4F4F5` |
| 次要文字 | `#838383` | `#A1A1AA` |
| 分段底色 | `#E9E9E9` | `#2B2C2F` |
| 强调 | `#FFD12E` | `#FFD12E` |

- 主题默认跟随系统；配置页可覆盖亮色/暗色/跟随系统，选择需持久化。暗色下的实际文字与控件对比度须在验收时测量，令牌表不代替对比度结论。
- 保留近白背景、圆形控件、充足留白与黄色强调色；不复制任何参考产品的图案或名称。

## 2. 侧栏与文字 logo

- 侧栏顶部为文字 logo：`Relay` 独占一行，字距约 `0.14em`（Android 实现 23sp / letterSpacing 0.14em）；`by OpenALC` 排其右下，字号约为 `Relay` 的 45%（约 10sp），颜色为次要文字色。
- 侧栏含两个可独立展开的菜单与一个页面入口：
  - 「设备」：展开已配对设备（名称 + SIM 标签）；设备项进入设备详情。空列表提供配对动作。
  - 「邮件」：展开邮箱账号（地址 + 连接状态）；账号项筛选邮件。另有添加账号、连接测试与账号配置入口（正式接口开放前只显示未接通说明，不放假开关）。
  - 「配置」：独立配置页（主题、配对与撤销、邮箱管理、安全与同步状态）。
- 侧栏打开/关闭（遮罩、关闭按钮、系统返回）不得改变当前列表、筛选或草稿。
- 演示数据只能出现在「合成验证」入口，且必须就地标注「演示数据」。

## 3. 页面与导航

顶栏：左侧圆形菜单钮；中央双标签「短信／邮件」（`role=tablist`，选中态同步滑移）；右侧圆形搜索图标钮（无障碍名「搜索」）。

| 控件或入口 | 目的地 | 完成条件 |
| --- | --- | --- |
| 顶部菜单 | 侧栏 | 开合不改列表/筛选/草稿 |
| 「短信」标签 | 短信列表 | 保留滚动位置、来源筛选及草稿 |
| 「邮件」标签 | 邮件列表 | 保留滚动位置、账号筛选及草稿 |
| 搜索图标 | 当前频道搜索页 | 返回恢复列表；不跨频道混合结果 |
| 短信/邮件卡片 | 对应详情页 | 返回原列表及筛选 |
| 底栏左侧控件 | 短信=设备+SIM 选择；邮件=发件账号选择 | 显示当前选择；不复用为菜单 |
| 底栏发送控件 | 当前频道发送流程 | 未接通正式链路时禁用并说明原因，不跳页 |

- Web 独立路由（当前 hash 形式，历史原因见执行台账）：`/sms`、`/mail`、`/search/:channel`、`/sms/:id`、`/mail/:id`、`/devices/:id`、`/mail/accounts`、`/settings`、`/dev/synthetic`；`/` 重定向 `/sms`。生产构建不得公开未鉴权 collector。
- Android：自管返回栈 + `BackHandler`（零新依赖），9 个目的地，系统返回逐级回退。
- HarmonyOS：`Navigation`/NavPathStack 多页面，系统返回行为对齐 Android。
- 三端正式列表在数据链路开放前一律诚实空态（「正式同步未接通——待服务端开放」等），禁止伪造会话卡片。

## 4. 列表卡片

- 短信卡片：来源设备、SIM 显示名及**已确认**本机号码（不可靠时显示「号码未确认」）、发送方、正文缩略、时间、收发状态。
- 邮件卡片：收件账号、发件人、主题、正文缩略、时间、附件标记、未读状态。
- 两类列表覆盖：加载、空态、断网、无权限、同步失败、分页、来源筛选。

## 5. 撰写与发送

- 底部表面悬浮栏上方放较小收件方输入框：短信为一个号码；邮件为多个地址标签。主输入栏填正文。
- 短信页左侧为设备/SIM 选择图标并显示来源摘要；邮件页左侧为发件账号选择器。
- 发送前须再次确认（短信单条确认；邮件展示账号与全部收件方、附件超限提示）。当前阶段发送控件恒禁用并显示「正式链路未接通」。
- 草稿按频道独立保存；进程重启可恢复非敏感草稿元数据；含真实正文的草稿在正式链路开放时必须加密保存（当前两端代码内均有注释标注此待办）。

## 6. 频道切换

点击标签或在**列表内容区**左右滑动均可切换频道；选中背景与内容同步滑移，目标时长约 250 毫秒。输入框、附件预览、侧栏和详情页不触发切换；系统启用减少动态效果时取消位移（Android 按 `ANIMATOR_DURATION_SCALE==0`，Web 按 `prefers-reduced-motion`）。

## 7. 合成验证边界（原 v1 约定的存续范围）

- 三端原有的 PoC 能力整体收敛到「合成验证」入口：Web `/dev/synthetic`；Android 配置→开发→合成验证（原 `RelayInboxScreen` 并入）；HarmonyOS 配置页开发区内入口。
- v1 的数据边界继续有效：Android Room `outbox_events` 最近 50 条只读；Web loopback collector 按安装 ID 筛选（不是认证）；HarmonyOS 本机合成链路经 S1 配对。安装 ID 与合成凭证不得当作正式认证。
- 正式首页不得出现 PoC 操作、测试卡片或演示数据。

## 8. 验收要点

空态、加载/失败态、亮暗两态截图（手机/平板/桌面）、每个入口的目的地与返回、频道切换手势与 reduced-motion、发送禁用原因可见性、无障碍名称。浏览器视口不代替真机结论；正式 UI 完成不等于真实收发完成。

## 历史章节：v1（2026-11-05）首屏 PoC 规范

以下描述的是首屏 PoC 形态，正式界面的对应部分以本章上方 v2 为准；仅「合成验证」入口继续沿用本节。

| 区域 | 三端约定 |
| --- | --- |
| 背景 | 近白色 `#FAFAFA`，主文字 `#111111`，次要文字 `#838383` |
| 顶部 | 左侧圆形菜单；中间浅灰 `#E9E9E9` 双标签「收件箱／设备」；右侧圆形标记 |
| 空收件箱 | 保留留白，不放欢迎卡、统计卡或虚构会话 |
| 底部 | 白色圆角悬浮栏；左加号、中安装 ID/筛选、右黄色 `#FFD12E` 操作位 |

Android fixture/计数/暂停开关放菜单内；Web 输入安装 ID 手动读取 collector；HarmonyOS 底栏写「尚未连接服务」。验收分别检查空态、合成事件列表、底部输入、菜单、状态栏对比度、横向溢出。
