# Relay 正式 UI 与短信、邮件功能实施计划

- 状态：**待实施**。本文是交给实施 agent 的规格和后续审查清单，不代表代码已实现或平台已实测。
- 依据：仓库 `AGENTS.md`、[现有三端 UI 规范](../design/RELAY-UI.zh-CN.md)、[服务端 RFC](../architecture/RFC-0002-server-mvp.md)及用户对本轮界面、邮件接入与实施顺序的确认。
- 实施前先读取上述文件，区分现有合成 PoC、正式服务、提案接口和真机证据。本文不授权发送真实短信或邮件、不提供测试账号，也不授权部署或推送 Git。

## 1. 目标与实施边界

Android、HarmonyOS、Web 三端具备一致的短信与邮件浏览、搜索、撰写体验。短信由用户选定的已配对 Android 设备及 SIM 实际执行；邮件由自托管 Go 服务连接外部邮箱。三端分别使用 Compose、ArkUI、Vue 实现，共享视觉令牌、页面结构、文案和状态语义。

按以下顺序交付：先完成可导航、可检查的正式 UI；再建立正式加密数据和接口；真实短信与真实邮件链路并行开发，各自通过安全及实测门槛后开放。尚未接通的操作应说明原因，不能返回假成功。现有 Web collector、Android 合成短信 PoC、HarmonyOS 本机合成交换必须与正式业务隔离；合成元数据不能冒充真实会话。

已确定的范围：

- 通用邮箱优先：用户手填 IMAP／SMTP 参数，服务端加密保存应用密码或授权码。首批只导入收件箱；Relay 新发邮件保留在本系统的已发送记录中，不导入邮箱原有已发送文件夹。
- 邮件首批支持主题、纯文本正文、回复、回复全部、抄送、密送和附件；收到的 HTML 邮件安全展示。首次默认导入最近 90 天；单封邮件附件总量默认上限 10 MiB，两个值均为服务端可配置项。
- 短信与邮件真实链路并行推进；搜索限定当前频道。三端都可浏览和撰写，短信始终由选定的 Android Agent 执行。
- 主题默认跟随系统，配置页可覆盖亮色或暗色；保持现有字体、近白背景、圆形控件、留白和黄色强调色。

## 2. 页面、导航与交互

### 2.1 导航表

| 控件或入口 | 唯一职责与目的地 | 完成条件 |
| --- | --- | --- |
| 顶部左侧菜单 | 打开侧栏；遮罩、关闭按钮和系统返回均可关闭 | 打开与关闭不改变当前列表、筛选或草稿 |
| 顶部「短信」 | 短信列表 | 保留滚动位置、来源筛选及短信草稿 |
| 顶部「邮件」 | 邮件列表 | 保留滚动位置、账号筛选及邮件草稿 |
| 顶部右侧搜索 | 当前频道搜索页 | 返回后恢复列表位置；不跨频道混合结果 |
| 侧栏「设备」 | 展开已配对设备；设备项进入设备详情 | 显示已识别 SIM、权限、最后观测时间和撤销状态 |
| 侧栏「邮件」 | 展开邮箱账号；账号项筛选邮件 | 另有添加账号、连接测试和账号配置入口 |
| 侧栏「配置」 | 独立配置页 | 包含主题、配对与撤销、邮箱管理、安全和同步状态 |

| 底栏左侧控件 | 短信页选择设备＋SIM；邮件页选择发件账号 | 显示当前选择，不能复用为菜单按钮 |
| 底栏发送控件 | 当前频道的校验、确认与发送流程 | 未接通正式链路时禁用并说明原因，不能跳到其他页面 |

Web 建立明确路由：短信、邮件、频道搜索、两类详情、设备详情、邮箱设置、全局配置各有独立 URL。Android 和 HarmonyOS 使用对应导航栈及系统返回行为。原有 PoC 操作移入仅供开发使用的「合成验证」入口；生产 Web 构建不能公开未鉴权 collector，Android／HarmonyOS 的验证按钮不占据正式首页操作位。实施代理须逐个核对当前点击后进入同一页面的问题。

### 2.2 顶部、侧栏和列表

- 顶部中央双标签改为「短信／邮件」，右侧圆形控件改为搜索图标，提供无障碍名称。保留原有字体与布局密度。亮色令牌为背景 `#FAFAFA`、表面 `#FFFFFF`、主文字 `#111111`、次要文字 `#838383`、分段底色 `#E9E9E9`、强调 `#FFD12E`。暗色建议背景 `#111214`、表面 `#1D1E20`、主文字 `#F4F4F5`、次要文字 `#A1A1AA`、分段底色 `#2B2C2F`；实际文字和控件对比度须验收。
- 侧栏顶部为文字 logo：`Relay` 独占一行，字距约 `0.14em`；`by OpenALC` 排在其右下，字号约为 `Relay` 的 45%，颜色使用次要文字色。保持 Relay 独立标识，不复制参考产品的图案或名称。
- 侧栏有「设备」「邮件」两个可独立展开的菜单，以及「配置」页面入口。「设备」显示设备名称与 SIM 标签；「邮件」显示账号地址与连接状态。空列表提供对应的配对或添加账号动作。
- 短信卡片显示来源设备、SIM 显示名及**已确认**本机号码、发送方、正文缩略、时间和收发状态。号码无法可靠读取时显示「号码未确认」，允许用户核对并设置标签，不推测号码。Android 号码读取受权限与可用性影响，实施时按[官方订阅信息文档](https://developer.android.com/reference/android/telephony/SubscriptionManager)核查。
- 邮件卡片显示收件账号、发件人、主题、正文缩略、时间、附件标记和未读状态。两类列表均覆盖加载、空态、断网、无权限、同步失败、分页和来源筛选。测试卡片只出现在独立验证入口并标为演示数据。
- 点击标签或在**列表内容区**左右滑动均可切换频道。选中背景和内容同步滑移，目标时长约 250 毫秒；输入框、附件预览、侧栏和详情页不触发频道切换。系统启用减少动态效果时取消位移动画。屏幕阅读器应读出当前标签及选中状态。

### 2.3 撰写、详情和搜索

- 底部白色或暗色表面悬浮栏上方放较小的收件方输入框。短信为一个号码；邮件为多个地址标签。主输入栏填写正文。切换频道时分别保存草稿，进程重启后可恢复非敏感草稿元数据；包含真实正文的草稿须加密保存。
- 短信页左侧用设备／SIM 选择图标替代加号，并显示当前来源摘要。发送前再次展示设备、SIM、收件号码和正文，要求用户确认**单条**发送。来源失效、权限缺失、号码无效或设备撤销时禁用发送并说明原因。
- 邮件页左侧改为发件账号选择器。正文获得焦点可进入完整撰写页，填写主题、To、Cc、Bcc、附件；支持从邮件详情回复和回复全部。发送前展示账号与全部收件方，附件超限时在提交前提示。清楚区分上传中、服务器已接收、邮件服务商已接受、失败和结果未知。
- 详情页显示完整来源、时间、内容、附件与状态轨迹。邮件 HTML 净化脚本、事件处理器、危险 URL 和主动内容；默认不加载远程图片。附件只在用户点击后下载，不自动打开或执行。
- 搜索按当前频道、当前 owner 范围和已选来源筛选；短信匹配发件方、收件方及正文，邮件另匹配主题。搜索词不进入日志或 URL 中的敏感诊断记录。清空搜索和返回均恢复原列表。

## 3. 正式服务的数据与接口

先在 RFC 定义业务接口、状态机和失败语义；完成一个可运行切片后才将其加入事实 OpenAPI。建议的资源边界如下，具体 HTTP 路径由接口 RFC 一次性确定，不能让三端各自发明协议：

| 资源组 | 最小操作 | 关键约束 |
| --- | --- | --- |
| 设备与 SIM | 列表、设备详情、可用订阅、用户确认的号码标签、权限和撤销状态 | owner scope；设备凭证不能读取其他设备 |
| 短信 | 分页列表、详情、频道搜索、创建单条发送命令、读取命令状态 | 显式确认、设备＋SIM 绑定、幂等键、限速、审计 |
| 邮箱账号 | 创建、连接测试、状态、撤销和删除 | 凭证只在设置时提交，后续不回显；撤销停止同步 |
| 邮件 | 收件箱分页、详情、附件按需下载、频道搜索、提交发送、读取提交状态 | account scope、附件大小限制、稳定 Message-ID 与幂等键 |

所有资源表带 `owner_id`；设备资源同时绑定 `device_id`，邮箱资源同时绑定 `account_id`。列表采用稳定游标。浏览器和其他 UI 客户端使用 owner 会话；Android Agent 使用独立设备凭证。状态变更沿用 Origin／CSRF 校验，分页与查询不得绕过归属检查。

只新增有序 SQLite forward migrations，不修改已发布迁移。手机号、短信正文、邮箱凭证、邮件正文、附件和发送命令负载在持久化前使用现有密钥环认证加密；AAD 绑定 owner、设备或账号、记录 ID 与负载类型。密钥不进入数据库备份；日志、URL、推送正文、Git 和测试证据不得出现凭证或真实消息内容。搜索在授权后对限定范围的密文记录解密匹配，不建立明文内容索引。密钥缺失、解密失败、数据库写失败均不得返回成功或 ACK。

### 3.1 邮件收发

服务端以加密连接使用 IMAP 收信、SMTP Submission 发信。用户输入邮箱地址、IMAP／SMTP 主机与端口、用户名、应用密码或授权码；凭证加密保存，只可替换和撤销，不回显。连接前限制端口与目标地址，校验证书和主机名；私网邮件主机仅通过服务器管理员显式允许列表接入。协议依据：[IMAP](https://datatracker.ietf.org/doc/html/rfc9051)、[邮件提交](https://datatracker.ietf.org/doc/html/rfc6409)、[邮件 TLS](https://datatracker.ietf.org/doc/html/rfc8314)。

首次只拉取最近 90 天的收件箱，之后按远端稳定标识增量同步；相同账号、文件夹与远端消息 ID 重复拉取不得重复入库。后台同步采用有界轮询、失败退避和可见的最近成功时间，不承诺即时到达。附件按需获取、限制大小并加密缓存；收到的 MIME、编码和 HTML 均按不可信输入处理。SMTP 前先持久化发送意图与稳定 Message-ID；若服务器可能已接受但连接中断，标记「结果未知」，不得自动再次提交。

邮件协议库应隔离在适配包，固定版本、提交 `go.sum` 并记录许可证。候选为 [go-imap/v2](https://github.com/emersion/go-imap)、[go-message](https://github.com/emersion/go-message)、[go-smtp](https://github.com/emersion/go-smtp)；实施前核查所选版本、安全修复和许可证，不能把协议库直接散布到 HTTP handler。

### 3.2 短信收发

Android 正式 Agent 与合成 PoC 分开。收到真实短信后先在本机加密落盘，再使用固定事件 ID 上传；服务端事务提交后 ACK。ACK 丢失后同 ID 重试返回去重结果；同 ID 不同内容应报告冲突，不覆盖已有记录。设备和 SIM 标识在每次发送前重新验证。

远程发送同时具备鉴权、用户单条确认、幂等键、限速、审计及领取／开始执行状态。页面区分「排队、设备领取、系统发送回调、运营商送达回执、失败、结果未知」；命令入队、推送接受、系统发送和送达是不同事实。可能已经调用 Android 发送接口而结果未知时绝不自动重发。多 SIM 使用用户明确选中的订阅，避免依赖默认卡；实施依据以 [Android SmsManager 文档](https://developer.android.com/reference/android/telephony/SmsManager)和目标机实测为准。

HarmonyOS 在此计划中作为远程浏览与操作客户端；短信由 Android Agent 执行。正式登录凭证须安全持久化；现有仅在进程内保存的 HarmonyOS 合成凭证不得当作正式认证方案。

## 4. 实施批次与各批验收

1. **设计与 UI**：更新共享设计规范和三端页面导航，完成侧栏 logo、菜单、短信／邮件列表与详情、搜索、撰写、来源选择、亮暗主题及动画。每个可见按钮有唯一职责；真实接口未就绪时显示明确状态，发送不可伪成功。保留原 PoC 自动化，验证入口与正式首页分离。
2. **正式数据基础**：完成迁移、认证加密、owner／device／account 范围、分页、搜索、附件存储、发送状态和审计。仅用合成正文与受控协议端点验证；密文篡改、错误密钥、回滚和重启都须有测试。此批未通过前真实数据入口保持关闭。
3. **并行接入**：邮件链路实现通用账号连接、收件箱增量同步、附件及提交；短信链路实现 Android 正式入站、选 SIM 和单条发送状态机。各自独立功能开关与验收记录，不以一条通过推断另一条通过。
4. **三端集成与部署门槛**：三端接入相同正式 API；检查断网、重启、撤销、重复与结果未知。Rocky Linux 的 HTTPS、备份／恢复、密钥分离及权限核查通过后，才能逐项开放真实功能。实际域名、主机和证书配置须在部署任务中核对，不能从现有资料猜测。
